# /speckit.lx.close — ритуал закрытия задачи

Проведи текущую задачу через полный ритуал закрытия LX. Выполняй по шагам,
показывай результат каждого шага, ничего не коммить в git (см. agent-file: git — только по указанию).

## Вход
- Определи текущую фичу из `.specify/feature.json` (каталог `specs/NNN-…`).
- Прочитай `spec.md`, `plan.md`, `tasks.md` этой задачи. Собери дифф реализации.

## Шаг 1. implementation_report.md
Создай/обнови `specs/NNN-…/implementation_report.md` (проза — русская) со секциями:
- метастрока `**Дата:** YYYY-MM-DD · **Статус:** <M|S|C>`;
- `## Итог` — что закрыто (со ссылкой на исходную боль/жалобу, если была);
- `## Изменения` — **Новые файлы** / **Правки** с полными путями и функциями;
- `## Решения` — обоснование неочевидных выборов;
- `## Проверки` — вывод build/test/vet (+ доменные проверки);
- `## Безопасность` — подтверждение, что секреты/боевые креды не попали в репозиторий;
- `## Вне scope / дальше` — что отложено.

## Шаг 2. Release notes (накопитель)
Добавь пункт в `docs/release_notes/upcoming.md` (создай файл, если нет):
- в `## EN → ### Highlights` и `## RU → ### Основное` — по строке с сутью изменения и ссылкой на `SPEC NNN`.
Это зеркалит CI-гейт Leadaxe: перед релизом `upcoming.md` переносится в `X-Y-Z.md`.

> Гейт релиза (тот же, что в CI) можно прогнать локально:
> `bash .specify/extensions/lx/scripts/bash/check-release-notes.sh <version>`
> — падает, если для версии нет непустого `docs/release_notes/<slug>.md`.
> В CI встраивается job из `ci/release-notes-gate.yml`.

## Шаг 3. Статус SPEC
Обнови front-matter `spec.md`: `Status:` → `Merged (M)` (влито в develop), либо `Shipped (S)` /
`Complete (C)` при привязке к релизу; заполни `Release: vX.Y.Z`, если известно.
> Статус живёт во front-matter, имя каталога `specs/NNN-…` не переименовывается.

## Шаг 4. Трассировка
Запусти проверку `/speckit.lx.trace` (или выполни её логику): убедись, что
ключевые изменённые файлы несут маркер `// SPEC NNN`, а раздел «Связи» в spec.md
корректно указывает `Depends on`. Допиши недостающие маркеры и ссылки.

## Шаг 5. Карта корпуса
Перегенерируй входную точку корпуса:
`bash .specify/extensions/lx/scripts/bash/spec-map.sh`
(обновляет `specs/README.md`: таблица NNN·название·Type·Status·INV·дыры + mermaid-граф
зависимостей из `Depends on`; файл помечен AUTOGENERATED — руками не править).

## Шаг 6. Отметка в tasks.md
Проставь `[x]` во всех пунктах фазы «Закрытие».

## Выход
Кратко отчитайся, что сделано на каждом шаге, и перечисли файлы, которые предлагается закоммитить
(коммит — вручную/по явному указанию). При коммите — формат из
[`docs/COMMIT_CONVENTION.md`](../../docs/COMMIT_CONVENTION.md): `type(area): subject SPEC-NNN (Phase N)`
(ссылка на спеку — в конце subject'а; `(Phase N)` — когда есть фаза).
