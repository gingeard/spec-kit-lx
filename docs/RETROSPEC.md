# Ретроспецирование существующего проекта (Leadaxe)

Обратный проход `код → SPEC` для молодого проекта: задокументировать «что есть и почему»,
не переписывая код. Лучший момент — сейчас, пока рациональ решений жив в голове.

Инструменты (в `lx-flow-ext`):
- `scripts/bash/spec-inventory.sh` — детерминированный инвентарь слотов (git + модули + теги), без LLM;
- команда `/speckit.lx.retrospec` — реверс одной описательной спеки (Status=Complete);
- `workflows/retrospec-fanout.js` — опциональный fan-out по всему инвентарю.

## Шаг 1. Constitution (до спеков)

```
/speckit.constitution
```
Зафиксировать инварианты и запреты по реальному коду — на них будут ссылаться ретро-спеки.

## Шаг 2. Инвентарь слотов

```bash
bash .specify/extensions/lx/scripts/bash/spec-inventory.sh > SLOTS.md
# опции: --since v1.0.0 · SRC_DIRS="core internal ui" ...
```
Скрипт предлагает слоты из значимых коммитов (feat→F, fix→B, refactor/perf→R), модули-подсистемы
и релизные теги; нумерация продолжает существующие спеки.

**Курировать вручную (обязательно):** единица спеки = **способность/решение**, а не коммит и не файл.
Схлопни родственное, выкинь служебное, уточни имена. Цель — десятки слотов, не сотни.

## Шаг 3. Реверс по каждому слоту

Последовательно:
```
/speckit.lx.retrospec  008 F core/config/subscription — парсер подписок
```
Или параллельно (fan-out) — см. Шаг 3′.

Команда для каждого слота: читает код + git + Constitution, применяет **кислотный тест**
(если спека лишь пересказывает код — не создавать), собирает descriptive-SPEC
(Status=Complete/Shipped, Проблема из коммитов с пометкой `[реконструкция]` там, где домыслено,
инварианты, поведение-как-есть, Depends on из графа импортов) и **предлагает** маркеры
`// SPEC NNN` (не проставляет сам).

### Шаг 3′. Fan-out (опционально)

Один агент на слот, параллельно. В своей сессии в корне проекта:
```
Workflow({ scriptPath: ".specify/extensions/lx/workflows/retrospec-fanout.js",
           args: ["008 F core/config/subscription — парсер подписок",
                  "009 B ui — мерцание иконки в трее",
                  "010 R core — расщепление монолита"] })
```
(это multi-agent оркестрация — запускается явно, в сессии пользователя).
Проще без Workflow — раздать слоты обычным субагентам, по одному на слот.

## Шаг 4. Свести и проверить

```
/speckit.analyze              # согласованность корпуса спеков
/speckit.lx.trace        # висячие Depends on, инварианты без маркеров в коде
```
Проставить подтверждённые маркеры `// SPEC NNN` в коде.

## Дисциплина

- **Кислотный тест каждой спеки:** несёт ли она то, чего в коде нет (намерение, отвергнутые
  альтернативы, инвариант)? Если нет — не плоди, консолидируй.
- **Реконструкцию помечай `[реконструкция]`** — не выдавай догадку за факт; на молодом проекте
  git беден на «почему», рациональ достаём из головы, пока помним.
- **Приоритет:** несущие/инвариантные модули — плотно; длинный хвост — тонко или пропустить.
- Статус ретро-спеки — сразу `Complete/Shipped` + `Release:` (из тегов/CHANGELOG), не `New`.
