# Changelog

All notable changes to the LX preset + extension for Spec Kit.
Format loosely follows [Keep a Changelog](https://keepachangelog.com/).

## [1.0.0] — 2026-07-10

Initial public release. Verified against `specify-cli` 0.12.7 / 0.12.8.dev0.

### Preset (`lx-preset`, id `lx`) — 8 templates + 2 command wraps
- Core overrides: `spec`, `plan`, `tasks`, `constitution`, `checklist`, `agent-file`.
- Additive: `audit-spec` (severity findings P0–P3 + mandatory refuted-by-verification),
  `invariants` (per-spec invariants doc — records as a test-coverage contract).
- Command wraps (`strategy: wrap` — keeps core, adds LX rules): `speckit.specify`, `speckit.implement`.
- Invariants model: two tiers (Constitution umbrellas / local per-spec records);
  three-line record `name → EARS contract → bindings (code · test · provenance · §umbrella)`;
  provenance is prose (`R<n>` / `§Const` / incident) — no git hashes (code marker + `git blame`
  recover the commit); spec keeps a terse index; coverage gaps (`тест: —`) surfaced explicitly.
- Borrowed from Kiro: EARS phrasing for acceptance criteria and invariant contracts
  (`WHEN/IF/WHILE/WHERE … system SHALL …`, `NEVER`); Decision Documentation block in plan
  (Context → Options → Decision → Rationale → Implications).
- Readability rules baked into templates: cold-reader (jargon glossed at first use, goal with
  verbs, readable before requirements); project-cipher/notation legend (one symbol = one meaning);
  telegraph items split; visual conventions (tables, fenced blocks, mermaid incl.
  stateDiagram-v2/sequenceDiagram, GitHub alerts, `<details>`, box-drawing, ```diff,
  `~~strike~~`, LaTeX `$…$`, footnotes, clickable code-map paths, closed emoji status vocabulary).

### Extension (`lx-flow-ext`, id `lx`) — 5 commands, 1 hook, scripts, workflow
- Commands: `speckit.lx.report`; `speckit.lx.close` (closing ritual: report → release notes →
  status → traceability → corpus map); `speckit.lx.trace` (verifies markers, named tests,
  index↔records sync; `--stubs` generates red-phase test skeletons from coverage gaps);
  `speckit.lx.retrospec` (reverse code→spec; `--full` for as-built plan/tasks/report/invariants);
  `speckit.lx.audit` (codebase audit in the audit-spec genre).
- Hook: `after_implement` → offers the closing ritual.
- Scripts: `spec-inventory.sh` (git history → curated spec slots);
  `check-release-notes.sh` (release-notes gate + `ci/release-notes-gate.yml` job);
  `spec-map.sh` (deterministic corpus map → `specs/README.md`: table + mermaid dependency
  graph; any 3-digit spec numbers incl. 100+, paren annotations stripped before parsing,
  edge only for existing folders, AUTOGENERATED overwrite guard).
- Workflow: `retrospec-fanout.js` (parallel reverse-speccing, one agent per slot).

### Notes
- Git branching intentionally NOT bundled (honours "git only on request"); do not install the `git` extension.
- Methodology derived from Leadaxe (https://github.com/Leadaxe); this adaptation is MIT-licensed.
